# Bounded synthetic performance workflow

Never target production, a VPS, Aramex, Salla or Shopyzee. Preserve application throttles. No public tunnels or external notifications. Use the published development Compose stack and explicit disposable databases only.

1. `docker compose run --rm --no-deps api php artisan test --compact tests/Performance` runs four opt-in kernel/real PostgreSQL/Redis benchmark tests. Fixtures are exact `testing`/`clicktoship_test`; migrations/reset are disposable. It samples 18 named operations, public/private source checks, 100 shipment/100 source-order records, 20 requests per common case, 10 synthetic exports and 3 imports per 1,000-row format. Login asserts bcrypt cost 12 and samples valid/existing-wrong/missing-account work separately; generic negative statuses are asserted as422. Unique simulated client IPs represent separate actors/requests within unchanged rate limits; do not interpret this as bypass permission for real clients.
2. `./scripts/prepare-browser-tests.sh --rebuild` resets only guarded `clicktoship_e2e`. With a private umask, execute `docker compose exec -T api php tests/Fixtures/phase16-load.php > /tmp/phase16-load-fixture.json` and `chmod 600` it. It creates four isolated synthetic principals, merchant-bound least-privilege 15-minute tokens, private test passwords, two owned organizations and 50 drafts per primary merchant, never submissions/holds/payments. Do not print or commit this file.
3. `python3 scripts/qa/http_load.py --fixture /tmp/phase16-load-fixture.json --output /tmp/phase16-http-load.json` only accepts loopback HTTP, refuses redirects/expired/non-private fixtures, caps concurrency 1/2/4, 264 total requests, five-second I/O and a 60-second submission deadline. It samples real Nginx/authenticated merchant APIs, concurrently replays one draft command four times (one resulting ID), and exercises CSRF/cookie-authenticated organization switching with a current-context check after every switch. No test credentials are printed. Output has counts/latencies/bytes, never tokens/payloads.
4. Record Node/PHP/PostgreSQL/Redis/OS/container versions, CPU/memory limits and competing workload with `docker info`/`docker stats --no-stream` without dumping configuration or environments. Record raw kernel metrics/EXPLAIN locally, aggregate into BASELINE. CPU milliseconds refer only to the PHP process; Docker samples are observations, not whole-system utilization guarantees.
5. Run actual Redis worker probes and independent-process/financial/shipment/export races in the full suite. Queue wait includes process startup; it is not steady-state Horizon capacity. Kill only the isolated export test process at an explicit scanner barrier; reclaim only its expired lease.
6. Do not run destructive tests or outages on normal services. `scripts/qa/restore_rehearsal.py` creates an isolated internal Docker network/cluster and tests dependencies there. Restore normal development with `scripts/start.sh` after all E2E/QA work. Never flush normal Redis or use `down -v`.

Nearest-rank p50/p95/p99 are observed samples. With 3/10/20 observations, p99 often equals the maximum and is not a reliable population tail estimate. The development PHP server, fixture/cache state, fake external adapters and shared host invalidate production SLA/capacity claims. Report HTTP status errors, source query counts, SQL plans and payloads alongside latency. Stop on wrong target, gate violation, failed authorization, unexpected side effect, resource ceiling or high error rate.

Before staging acceptance: agree tenant/data sizes, anonymized distributions, arrival model, burst/sustained duration, queue fairness, SLOs, contention budgets and approved RPO/RTO. Repeat 1/2/4 then separately approved higher concurrency against production-like isolated infrastructure; include warm/cold caches, multiple merchants and same-merchant locks. Long soak/restore, object-version consistency and real-provider sandbox behavior remain separate unexecuted prerequisites. No existing throttle/timeouts/assertions are weakened to make results pass.
