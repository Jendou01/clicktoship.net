# Phase 10 — International customs preparation

Customs extends immutable Shipping revisions with optional typed customs data; it owns versioned declarations/items/readiness, merchant profile versions, draft document work and global country requirement proposals/reviews. Shipping ownership, pricing snapshots, tracking state and the single financial ledger remain authoritative and unchanged. No carrier call, customs filing, legal clearance, wallet operation or notification is enabled.

Customs snapshots bind tenant/shipment/revision and canonical hash. Saving a declaration creates a Shipping-owned draft revision through its application boundary; edits invalidate previous quote/review/document applicability. Standard and bulk drafts can carry the same normalized customs payload. A country-code catalogue validates ISO alpha-2 syntax/identity only, never route entitlement. Currently only SAR is enabled by the existing financial policy; data retain explicit currency/exponent and never convert FX. Values are integer minor units; quantities are whole units; net/gross weights are total line grams, not floating per-unit values. Package allocations must sum to each line quantity and stay within revision package bounds; optional allocated grams must agree with line/package totals.

Country rules are evidence-backed proposals with independent current-MFA review and immutable history. Reviewed configuration can identify missing declared fields, but external verification and runtime enablement remain code-gated false. No administrative flag can declare legal compliance or activate a route. Incoterms 2020 entries are selectable merchant declarations, not carrier offerings. Restricted-category flags require explicit review and never imply universal prohibited-goods policy or automatic approval.

Commercial invoice/packing-list PDFs use TCPDF (Unicode/Arabic font shaping), typed text cells only: no HTML parser, remote URLs, uploaded PDFs, JavaScript, signatures or embedded customer content. This dependency supplies PDF layout/fonts rather than a bespoke PDF writer. Every page is visibly DRAFT / NOT CUSTOMS CLEARANCE. Document numbers are server-allocated per merchant/type under lock, unique and immutable. Jobs carry only encrypted IDs; PostgreSQL requests/leases/results are durable with bounded retry, credential/revision rechecks and crash recovery. Original generated bytes are encrypted on the existing private disk; scanner/checksum and storage/privacy gates remain fail-closed. Default scanner does not approve a download. Production generation/download remain disabled pending approved storage/scanning/retention. Testing can inject an isolated scanner; synthetic PDF artifacts are evidence of rendering only, not legal documents.

Existing shipment_documents are label-only, synthetic-only, with incompatible ownership/provenance constraints. Customs documents therefore use a separate version/reference table while reusing Shipping DocumentScanner, private local disk, authorization/audit/header conventions; no public URLs or duplicate shipment ownership table. Old documents are explicit historical drafts; stale jobs cannot produce current documents after a shipment edit. All exports reauthorize current membership/scopes; administrative target reads/review require current MFA and independent expiring session-bound grants. Rule review never approves a customer's shipment. Raw payloads and review reasons are encrypted; immutable history cannot be edited/deleted. Runtime downgrade refuses retained customs history.

Country legislation, carrier customs field contracts, Incoterms/duty payer eligibility, fees/taxes/insurance, regulated goods policy, document certification/numbering and production privacy/storage/scanning remain external approval gates. DDP selection never enables collection. No authority declarations, official HS classification, government signatures or clearance claims are generated. Phase 11 is not authorized.
