# Phase 7 — Shipment management and activation boundary

## Scope and source
Base main `19289f88d0b76b330647bf09aad651b0f424efe0` (PR #5). Follow AGENTS, Technical Blueprint and the explicitly approved Phase 7 policies. No Phase 8, deployment, carrier request, normal synthetic shipment, payment or real financial activation.

## Ownership and state
Shipping owns encrypted drafts/revisions, readiness, immutable submissions, events and durable outbox. Pricing owns immutable single-use quote acceptance. WalletBilling owns all hold/financial mutations through its existing double-entry posting engine. Carriers owns operation lifecycle/attempts, capability gating and provider-neutral outcomes. Pickups owns associations, commands and history. No second ledger, mutable financial history or globally unique AWB assumption.

Shipment: draft/ready -> queued -> sending -> accepted/rejected/unknown. Local cancellation is draft/ready only. Blocked is a proven-unsent queued command. Financial and document states are separate. Unknown carrier evidence remains terminal even after an independently approved effective resolution; reconciliation events expose that resolution without rewriting the carrier operation. Capture failures retain accepted/capture_pending, and recovery retries only local settlement. Conflicting supplementary definitive evidence is retained, flagged, and cannot drive automatic correction; conflicting definitive reconciliation proposals/approvals are refused.

Draft origin/destination/optional return address/contact/package/customs data is encrypted in an immutable typed revision rather than duplicated into mutable child projections. Revisions bind both full canonical input and pricing-subset hashes. Local international readiness requires manufacture country and item details; these are not a customs compliance determination. Carrier validation, package serialization, payer/Incoterms/DG/insurance/COD entitlements remain evidence/policy gates. SAR only is enabled, with exact integer minor units and no FX. COD is not enabled.

## Quotes and transactions
Quote acceptance requires current merchant/rates/shipping permissions, ready state and expected version; quote inputs must equal canonical shipment pricing inputs. It is single-use across submissions/revisions. Every edit creates another immutable revision and invalidates the current acceptance. Existing public price snapshots are reused without exporting carrier cost or margin. Quotes must be valid at reserve and again at the dispatch fence. Once dispatch starts, accepted price remains the settlement basis; no silent repricing.

Reserve + carrier intent + immutable submission + outbox + event/dedupe commit atomically in PostgreSQL. No HTTP in a database transaction. Submission actor, authentication version and exact session/token identifiers persist; worker rechecks current scope/membership/status/credential before dispatch. The default gateway calls the unchanged Phase 6 capability registry and stops before any hold. There is no runtime synthetic switch. Even a replaced gateway cannot reserve in a non-testing environment or normal database.

Dispatch commits protection and sending marker before network. A crash after that marker is ambiguous, including death before transmission. HTTP errors/timeouts/lost/malformed responses are not definitive nonacceptance. A normalized outcome is stored in a separate committed observation before settlement. No automatic external creation retry; test outcomes implement an explicitly synthetic provider-neutral protocol, never fabricated Aramex responses.

## Financial resolution
Protected/unknown flags remain monotonic. The additive migration preserves the Phase 4 posting engine except narrowly allowing capture/release backed by an immutable matching financial_hold_resolution. Such evidence resolution is hard restricted to isolated test databases; no production accounting gate is relaxed. Evidence must match submission, wallet, hold, currency, amount and outcome. Unknown outcomes additionally require an independent approved reconciliation. No refund is triggered by label/pickup failure or cancellation. Existing finance refund/reversal bounds are unchanged.

A frozen wallet/inactive merchant cannot be bypassed for settlement: retain pending state and protected funds until permitted or until an approved operational policy is supplied. Capture/release failure must not lose carrier evidence or lead to shipment resubmission. Internal settlement replays use permanent business keys. Normal runtime manual evidence interpretation/execution awaits verified evidence standards and launch/accounting approval; no public endpoint accepts a trusted outcome flag or raw carrier response.

## Concurrency and recovery
PostgreSQL merchant-root serialization protects tenant changes. Quote operations take Pricing's shared catalog lock before merchant; dispatch additionally takes the existing global platform-security lock before catalog/merchant/actor/session/carrier checks, preventing administrative authorization/configuration changes from crossing the dispatch fence. Existing finance commands lock merchant then wallet/hold. Identity changes serialize on the same user/session rows. Release locks before network; changes after the committed fence cannot recall an in-flight request and instead require recording/reconciliation.

Encrypted one-try ProcessShipment jobs use the shipments queue and clear tenant context in finally. `shipping:outbox` can republish committed work; `shipping:recover` runs every minute and reads PostgreSQL directly, including when Redis loses a job. Unique submission/hold/quote/command identities and state transitions reject duplicate local effects. Five-minute stale sending detection quarantines to unknown; this threshold never releases a reservation. Outbox delivery receipt follows settlement or durable unknown protection. No exactly-once network guarantee is claimed.

## Pickups and documents
Pickup drafts freeze associated shipments/window/timezone. The local draft window is bounded to 24 hours; actual carrier scheduling/cutoff/fee policy remains unapproved. Creation requires accepted/captured shipments with identical origin and carrier account, no conflicting active association, and current authorization. Durable immutable pickup commands reuse carrier operations. Creation/cancellation never retry after a sending marker; stale markers become unknown. Pickup cancellation never cancels a shipment or changes money. Shipment cancellation after dispatch remains unsupported.

Private document storage uses Laravel's private disk abstraction with random server-generated keys, bounded PDF fixture input, checksum, quarantine and scanner interface. Default scanner rejects all documents. No public upload/URL-fetch endpoint, redirects, public label URL or sensitive logs. Downloads authorize current tenant/permission under the merchant lock, verify integrity, audit access and return private/no-store, nosniff, sandbox, attachment headers. Revocation prevents later requests. Synthetic ingestion/downloads require testing plus isolated database; real labels remain blocked pending approved storage region/provider, scanning and retention policies. A syntactic PDF check alone is not a malware scan.

## RBAC and API
New granular permissions: shipments.write/submit/cancel/documents plus existing read/pickup capabilities. Built-in Owner/Admin/Shipping Manager/Shipping Operator receive operational grants; finance does not automatically receive recipient/document access. Platform shipment review/reconciliation uses exact merchant, independently approved session-bound grants and recent MFA. Reconciliation checker also needs finance.reconcile. No member of the target merchant can resolve its administrative case. Maker/checker grant authorities, credential versions and sessions are revalidated under the existing platform lock. No Super Admin bypass.

OpenAPI describes all REST resources. EN/AR screens cover draft wizard, listing/detail/quote/events, private document status, pickup drafts and target-granted exceptions/reconciliation. Normal submission, real downloads and financial execution buttons truthfully remain disabled.

## Remaining launch requirements
Current V2 schemas/scrubbed responses, approved sandbox access and non-billable test policy, account/service mappings and entitlements, reference lookup semantics, international/COD/customs policies, storage/scanning/retention, suspended-obligation policy, accountant/regulatory acceptance and least-privilege runtime role deployment. None is inferred from legacy SOAP or successful synthetic tests.

## Post-Phase 7 UI and QA follow-up

Shipment directory read projections now add only current-tenant description and recipient name. Full addresses, phone, private pricing and carrier credentials remain excluded. Detail selection uses a shipment UUID query parameter and always reloads through existing tenant authorization; locale links allowlist this identifier only, retaining merchant selection in the server session. This is not an access grant or cross-tenant selector. No financial or carrier execution rules changed.

Read-only `schema:verify` checks critical shipment bindings and history guards before browser fixtures. Disposable browser rebuild is explicitly restricted to testing/clicktoship_e2e; applied migration names cannot substitute for integrity verification.
