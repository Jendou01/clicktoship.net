# Phase 15 Analytics architecture

Base main58fadd7cb18d1fbe36c1eaaf8347cb36765b2e69 (Phase14 PR14), verified before branching. Analytics reads existing module sources with predefined typed definitions and reuses ShippingAccess/current origin locks, Operations ReadAuthority/PlatformSecurity, Metrics, Approvals, wallet currency conventions and existing encrypted Horizon job patterns. No duplicated business engine/cache/materialized store. See ../analytics/METRIC_DICTIONARY.md (recorded before code) and REPORT_CATALOG.md.

A necessary additive migration owns only export records/events, permissions and read/recovery indexes. Current merchant source permissions intersect token abilities; platform counts require browser/recent MFA/source permissions and never confer private grants. Private finance remains on existing exact-granted routes. Query deadlines5s, bounded date ranges/keysets/rows/bytes and no caller-defined SQL or columns. No money float/FX/revenue claims. Synthetic provenance is not verified carrier success.

Exports remain fail-closed in normal runtime pending storage/scanning/retention approval. Isolated tests exercise encrypted local artifacts and explicit clean scanner only. Current actor/origin/role/merchant/MFA are checked at enqueue, generation and download; leases, generation fences, immutable audit, idempotency, limits and cleanup protect retries/crashes. No public object URLs, PII filenames or raw queue/log payloads. Source data is read at generation, not request time; rows include generation timestamp and bounded source definitions. Retained orchestration/audit prevents unsafe normal downgrade; only disposable databases are reset in tests.


The supplied Technical Blueprint was reviewed for Reporting, data ownership and accountant-approved posting boundaries. Its reporting component is implemented as read models, not a second financial engine. Platform merchant lifecycle additions count persisted `merchant.status_changed` audit events by `metadata.to` and `merchant_verification_decisions.outcome`, never decrypt audit reasons. Initial creations are registrations; the activation series counts recorded reactivations to active. Current-state groups are separate. Day/week/month rebucketing preserves underlying event totals and uses UTC Monday/calendar month starts.

The existing Operations tracking reader accepts an optional merchant scope applied to every work/case/event/binding/projection query. Platform calls retain null/global scope; merchant analytics never falls back to global. A cross-merchant regression creates actual synthetic tracking work and proves it cannot affect another merchant's report. Platform aggregate read pages remain live source observations. Exports use a repeatable-read source transaction, then reauthorize publication after scanning; snapshots are generation-time observations, never historical statements or private global financial disclosures.

Source read statements have a 5-second PostgreSQL deadline. Jobs use existing Horizon's bulk queue, one attempt per delivery with durable bounded recovery (not unbounded queue retries), a 45-second job timeout and a 60-second lease. Queue payload is encrypted and contains only export ID. At most 3 generation attempts/staging paths are recorded, privately and immutably, so expiry recovery can clean even an artifact written late by a crashed/expired worker. No broad filesystem deletion or public storage listing is used.
