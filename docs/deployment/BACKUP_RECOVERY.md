# Authenticated backups and recovery

`backup.py` creates local consistent PostgreSQL custom dumps, a quiesced private object tar and encrypted per-object manifest in a private temporary directory. It validates dump catalog, encrypts each with **OpenSSL CMS AuthEnvelopedData / AES-256-GCM** to an explicit recipient certificate, writes ciphertext SHA256 checksums and deletes temporary plaintext on exit. The RSA private recovery key is never needed by backup creation and must be escrowed independently of archive and APP_KEY. Normal operation uses a protected PostgreSQL service/passfile (0600), not passwords in argv; the alternative container source is restricted to `cts17-*` disposable rehearsals.

The caller must quiesce writers before DB/object snapshot, verify object symlink/path/ownership boundaries and provide a trusted approved recipient certificate. Secret service/passfiles, encryption keys and outputs belong outside Git on protected encrypted host storage. No software passphrase is hardcoded. Current tool is a bounded initial local mechanism; streaming quota/large-volume/versioned-object storage/PITR need actual-host design. Local plaintext temporary data requires encrypted disk and operational secure-temp policy; unlink is not guaranteed physical erasure on SSDs.

No offsite upload or deletion/retention is automated without an approved destination/policy. A locally encrypted file is **not** an off-host backup. Require independently verified upload receipt, authenticated retrieval/decryption, object hashes, exact release/schema/key identity, access controls, region, retention/object-lock and actual restore. No offsite provider/key custody/approved retention is supplied in Phase17: gate remains BLOCKED.

Restore only into a fresh approved isolated target. Verify ciphertext digest against protected manifest, decrypt with `openssl cms -decrypt -binary -inform DER -recip <certificate> -inkey <escrow-key>` into protected storage; abort on any GCM authentication failure and never use partial decrypted output. Verify dump catalog and restore roles/function ownership separately, then pg_restore with error checking. Portable --no-acl dumps do not preserve restricted function ACLs. Reapply reviewed runtime-grants.sql before any runtime access; it explicitly revokes PUBLIC execution on finance_command and restores only the existing finance capability. Verify pg_proc/aclexplode and actual runtime denials; never assume schema restoration preserves access policy. Restore private encrypted files only through a safely bounded extraction into a new directory (never extract untrusted archives into a live path); reject absolute/parent/symlink/device paths and verify the encrypted object manifest. The tar is an operator-owned backup artifact, not an upload/parser interface.

Check schema, all tenant identities/immutable audit/ledger balance, encrypted row/object samples with matching APP_KEY and wrong-key rejection, expiry and unknown-provider outcomes. Invalidate restored sessions/tokens/grants under approved incident policy, do not recover stale authority from Redis, and independently reconcile unknown financial/carrier work before resuming. Rotate/revoke service/gateway credentials if compromised. Rotation of APP_KEY requires versioned ciphertext migration and preserved approved previous keys; never run key:generate on retained data.

Local rehearsal checks authenticated encryption/decryption, corrupted ciphertext rejection and restored24 migrations on a separate disposable DB. Phase16 has broader row-fingerprint/key/ledger/object/outage evidence. Neither establishes actual offsite recovery, production key custody/PITR, approved RPO/RTO or cross-version incident readiness. See operations/BACKUP_RESTORE.md and ROLLBACK_RUNBOOK.md.
