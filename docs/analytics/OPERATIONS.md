# Analytics export operations and activation boundary

All normal-runtime artifacts/downloads are intentionally disabled. A request is auditable but fails with `EXPORT_STORAGE_NOT_APPROVED`; no bytes/job are published. `analytics.test_artifacts_enabled` only works in environment `testing` with exact database `clicktoship_test`/`clicktoship_e2e`. It cannot activate local/staging/production exports. The existing disabled scanner still rejects bytes unless an isolated test installs its explicitly clean scanner. Never change this to public storage or return object URLs.

Migrations add only report-owned metadata/events, source-read indexes and explicit built-in role permission mappings. Do not reset normal databases. Rollback refuses retained export history; treat this as retention protection, not a reason to delete audit records. Schema verification checks columns, immutability/identity triggers and all new indexes, including active-operation uniqueness.

The existing scheduler executes `analytics:recover` every minute. Existing Horizon bulk workers consume encrypted `GenerateReport` jobs containing only export ID. Redis is a wake-up mechanism; PostgreSQL owns requested filters/origin/status/leases/attempts. Recovery republishes queued/interrupted work, skips live leases, caps generation at three claims, and uses global/actor/merchant backpressure. Terminal and expired cleanup removes only privately recorded staging paths, revisiting expired records for late writes. Immutable event metadata remains retained. A hard crash does not justify deleting unrelated files or resetting a database.

Before any future normal activation, separately approve storage residency/retention/deletion, access and key policies, malware/content scanning, operator privileges, monitoring and resource/scale validation. Implement the approved adapter/gates in a separate review. Revalidate revoked sessions/tokens/roles, suspension, recent MFA, owner/tenant checks, download expiry and crash cleanup. No reviewed storage approval or production SLA is implied by current synthetic tests.

Financial/accounting, carrier, Commerce and notification activation gates remain independent. Report failures must not retry unknown carrier outcomes, release reservations, debit wallets or perform merchant actions. Exports are generation-time snapshots, not an accounting close or historical balance statement. For incident triage use export ID/state/sanitized error code and immutable events; do not log or copy credentials, SQL, artifact contents or customer data.
